## 一、架构总览（v4.0 定案）

```
┌─────────────────────────────────────────────────────────────┐
│  Fork 层（改官方最新版 cherry-studio 本体）                    │
│  ├── 管理路由 /v1/admin/*（agents/providers/skills/mcp/usage）│
│  ├── 独立管理 key（feature.api_gateway.managed_key）          │
│  ├── 泛化受管保护（managed_registry 旁路表 → 不可改/删）       │
│  ├── 热更新 IPC 刷新广播（写 sqlite → 渲染 invalidate）        │
│  ├── 锁死 UI（源码级改渲染组件加 managed 判断）                │
│  └── 禁用官方更新通道（改 feedURL 指向自建）                   │
├─────────────────────────────────────────────────────────────┤
│  Sidecar 层（独立进程，NSSM Windows 服务）                    │
│  ├── 连服务端 WS 2334 + 调 Fork 管理路由                      │
│  ├── 派发 Agent/模型/SKILLS（幂等）                           │
│  ├── 采集 ai_usage_record（模型+token）上报                   │
│  ├── 对账（list 比对期望清单）                                │
│  ├── 受管标记旁路表 managed_registry.db                       │
│  └── 自愈（Fork 升级失败回滚）                                │
├─────────────────────────────────────────────────────────────┤
│  服务端（server/, 端口 2334, FastAPI）                        │
│  ├── Web 管理后台（管理员登录 + 操作审计）                     │
│  ├── 花费监控模块（ai_usage_record 聚合 + 异常告警 + 停 key）  │
│  ├── agents_lib / skills_repo / lock_rules / gitbash_repo    │
│  ├── 设备注册表 + 设备分组 + 派发幂等                         │
│  └── 数据仓库（员工端用量聚合）                               │
└─────────────────────────────────────────────────────────────┘
```

## 二、需求 R1-R7 覆盖矩阵

| 需求 | 实现层 | 落地模块 |
|------|--------|---------|
| R1 模型统一管控 | Fork 管理路由 + Sidecar | `/v1/admin/providers` CRUD + 企_ 前缀约定 + managed_registry 隔离 |
| R2 Key 保护 | Fork + 服务端 | 独立管理 key + 花费监控异常停 key 重建 |
| R3 Agent 远程管理 | Fork 管理路由 + Sidecar | `/v1/admin/agents` CRUD + MCP/SKILL/数据打包 |
| R4 SKILLS 派发+版本 | Fork + 服务端 skills_repo | SKILLS 打包上传 → 版本管理 → 下发 |
| R5 锁死 UI | Fork 渲染层 | 源码级 managed 判断（隐藏删除/只读）+ lock_rules 远程迭代 |
| R6 数据采集 | Sidecar + 服务端 | 采集整个智能体工作目录（上下文+产出+用量，含对话内容，工作软件合规）→ 服务端分析 |
| R7 升级免疫 | Fork + 构建流水线 | 禁用官方 feed + 自建更新通道 + 增量 patch 适配 |

## 六、风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 热更新链路做不出（UI 不刷新）| 🔴 高 | 方案 A 复用官方 invalidateQueries；若失败降级方案 C（强制重启兜底）|
| Fork 适配成本（官方高频发版）| 🟡 中 | 增量 patch + 按需升级（重要功能/安全修复才追）|

| 管理路由写 sqlite 破坏事务 | 🟡 中 | 复用 AgentService/ProviderService 方法，不直写 |
| 花费监控误判异常 | 🟡 中 | 阈值 + 增速 + 单设备超限多维度；人工确认重建 |
