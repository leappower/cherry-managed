## 〇、本版与 v3.0 的差异（智能体 + 设置页管控细化）

v3.0 之后老板细化了两大块需求（智能体功能、设置页管控），v3.1 全部落地：

| 决策 | 内容 | 影响 |
|------|------|------|
| ① Git Bash 依赖 | CherryStudio 智能体依赖 Git Bash；后端监控员工端缺失则远程安装最新版 | 智能体可用性保障 |
| ② Agent 不可删 | 远程派发的智能体，员工端删除按钮隐藏 | 受管 Agent 不可被员工删除 |
| ③ Agent 全维控制 | 远程派发智能体的基础设置/提示词/工具/技能/高级设置全部可控制 | 智能体完整管控 |

**核心架构转变**：在 v3.0「补丁包 + 后端拉取」基础上，补齐「智能体生产打包链路」和「设置页受管项删除保护」两大闭环。

## 一、目标（一句话）

给公司内部做「CherryStudio 企业受管版」：**员工装官方版 + 打一个轻量补丁包，补丁包只打通后端链接；核心功能（模型/Agent/SKILLS/锁死规则）全部由后端拉取迭代；员工端受管项锁死不能改，但可自配自己的模型；公司模型 Key 不泄露；数据回采驱动进化；员工自己升级 CherryStudio 不破坏受管状态。**

## 四、交付形态（关键）

### 4.1 员工安装流程
```
1. 员工去 CherryStudio 官网下载官方版，正常安装
2. 员工双击我们的补丁包 cherry-managed-patch.exe
3. 补丁包安装：
   ├── 安装 Sidecar 常驻进程（打通后端链接）
   ├── 写入受管标记
   └── 首次运行注入器（锁死 UI 机制）
4. 完成，员工正常使用（受管版）
```

### 4.2 补丁包内容（轻量，不注入核心功能）
```
cherry-managed-patch.exe（NSIS 安装器）
├── Sidecar 常驻进程        ← 核心（打通后端链接）
├── 注入器（一次性）         ← 锁死 UI 机制（改 asar）
├── 受管标记写入            ← 标记 CherryStudio 为受管
└── 卸载器（控制面板可卸）
```

### 4.3 卸载逻辑
- 移除 Sidecar + 恢复受管标记
- CherryStudio 本体不动（员工还能正常用官方版）
- 控制面板可卸载

### 4.4 核心功能后端拉取（关键）
```
补丁包只装"壳"（Sidecar + 注入器）
        ↓
Sidecar 连上后端后，拉取所有核心功能：
  ├── Agent 模板
  ├── SKILLS 版本
  ├── 模型配置（企_ 前缀）
  ├── 锁死规则（UI 锁死哪些项）
  └── 补丁库（升级自愈用）
        ↓
改后端即可迭代，不重发补丁包
```

## 五、锁死 UI 远程迭代（R5 核心）

### 5.1 两层设计：机制固定 + 规则远程拉取
```
锁死 UI = 机制（怎么锁） + 规则（锁什么）
              │                │
         注入器一次到位      后端拉取，可远程迭代
```

| 层 | 内容 | 迭代方式 |
|----|------|---------|
| **机制** | 注入器（把锁死逻辑挂进渲染进程） | 补丁包装一次，基本不动 |
| **规则** | 锁死哪些项/隐藏哪些/只读哪些（JSON 配置） | **后端拉取，随时改** |

### 5.2 运作流程
```
后端 Web后台 改「锁死规则.json」
        ↓
员工端 Sidecar 定时/实时拉取新规则
        ↓
注入器把新规则应用到 CherryStudio UI
        ↓
员工端锁死界面更新（无需重装）
```

### 5.3 举例
- 今天锁死"模型设置页"，明天想加锁"MCP 设置页" → 后端改一行配置，员工端自动生效

## 六、升级自愈（R7 核心）

### 6.1 影响分层
| 组件 | 是否受 CherryStudio 升级影响 | 原因 |
|------|---------------------------|------|
| **Sidecar（独立进程）** | ✅ 不受影响 | 独立进程，不依赖程序文件 |
| **后端链接** | ✅ 不受影响 | Sidecar 独立连服务端 |
| **UI 锁死补丁（注入 asar）** | ❌ 会被覆盖 | 官方升级重写程序文件 |

### 6.2 自愈机制（guard.py 完整性校验）
```
员工端 CherryStudio 官方升级
        ↓
Sidecar 检测到版本变化/文件哈希变化（guard.py）
        ↓
Sidecar 从后端补丁库拉取对应版本补丁
        ↓
自动重打 UI 锁死补丁
        ↓
锁死界面恢复（员工无感，无需重装补丁包）
```

### 6.3 版本适配
```
注入器 = 版本适配层
├── 识别 CherryStudio 版本
├── 按版本选择对应补丁（补丁库存多个版本）
└── 打上该版本的 UI 锁死补丁
```
- 新版本 CherryStudio 出来 → 后端补丁库加一个适配补丁
- 员工升级 → Sidecar 自动拉新补丁重打
- **你只需维护后端补丁库，不用管员工端**

## 六·B、智能体功能细化（v3.1 新增）

### 6B.1 Git Bash 依赖自动安装（智能体可用性保障）

**背景**：CherryStudio 的智能体依赖 Git Bash 运行（Agent 是 claude-code 类型，需 Git Bash 作为终端环境）。员工端若没装 Git Bash，派发的智能体无法运行。

**机制**：后端监控 + 远程自动安装
```
员工端 Sidecar 连接服务端
        ↓
服务端检测该设备 CherryStudio 是否可用（含 Git Bash 依赖检测）
        ↓
若缺 Git Bash → 服务端下发安装指令（含最新版安装包 URL/内嵌）
        ↓
Sidecar 下载并静默安装 Git Bash 最新版
        ↓
回执安装结果 → 服务端更新设备状态（git_bash_ready: true）
```

**实现要点**：
- 设备注册时上报 `git_bash_installed` / `git_bash_version`
- 服务端维护 Git Bash 安装包（或指向官方下载最新版）
- Sidecar 静默安装（Windows 下 Git for Windows 支持 `/VERYSILENT` 参数）
- 安装完成后校验 `git --version`，回执

### 6B.2 远程派发智能体员工端不可删除（R3 强化）

**需求**：远程派发的智能体，员工端**删除按钮隐藏**，员工无法删除。

**实现**：
- 派发时给 Agent 打「受管标记」（`managed: true`）
- 注入器根据受管标记，在智能体列表/详情页**隐藏删除按钮**（受管 Agent）
- 只有服务端能通过 Sidecar 回收（`dispatch_agent action=delete`）

### 6B.3 远程派发智能体全维度控制（R3 强化）

**需求**：远程派发的智能体，以下全部可由服务端控制：

| 维度 | 内容 | 控制方式 |
|------|------|---------|
| 基础设置 | 模型、名称、描述、图标 | dispatch_agent 更新 |
| 提示词设置 | System Prompt / Instructions | dispatch_agent 更新 |
| 工具 | 工具启用/禁用 | dispatch_agent 更新 |
| 技能 | SKILLS 挂载/版本 | skills 字段 + skills_repo |
| 高级设置 | permission_mode、max_turns 等 configuration | dispatch_agent 更新 |

**实现**：派发的 Agent 完整定义（含全部维度）存服务端 agents_lib，Sidecar 按版本同步，员工端不可改（受管锁定）。

### 6B.4 智能体生产打包链路（Agent 打包 → 上传 → 版本管理 → 下发）

**核心：解决「远程派发 Agent 的数据包从哪来」**

**完整链路**：
```
1. 管理员在本地「调好的 CherryStudio」中调好一个智能体
2. 用我们提供的「打包 SKILLS」让该智能体把自身打包成派发包
3. 打包产物：agent-package.zip（含 agent.json + skills/ + mcp/ + data/）
4. 上传到服务端 Web后台
5. 服务端登记 Agent + 版本号（Agent 版本管理）
6. 服务端下发到目标设备组
7. Sidecar 解包 → 按 agent.json 创建/更新智能体
```

**打包 SKILLS（给调好的智能体用）**：
- 我们交付一个「打包 SKILLS」模板（类似已有 templates/SKILL-mll-review.md）
- 调好的智能体调用该 SKILLS → 自动收集自身配置 + 关联 SKILLS/MCP/数据 → 生成 agent-package.zip

**Agent 包结构（D3 复用）**：
```
agent-package.zip
├── agent.json            # Agent 定义（基础设置/提示词/工具/技能/高级设置）
├── skills/               # 关联 SKILLS 目录（含版本）
├── mcp/                  # MCP 配置
└── data/                 # 预设数据文件
```

**版本管理**：
- 服务端 agents_lib/{agent_name}/{version}/ 存储多版本
- 派发时指定版本，Sidecar 按版本同步
- 更新 = 上传新版本 → 下发；回收 = 移除

**SKILLS 版本管理（D4 强化）**：
- skills_repo/{skill_name}/{version}/ 存储多版本
- Agent 包引用 SKILLS 时指定版本（如 `skill-a@v1.2`）
- 更新 SKILLS = 上传新版本 → 下发到引用它的 Agent

## 六·C、设置页管控细化（v3.1 新增）

### 6C.1 远程派发模型平台不可删除（R1/R5 强化）

**需求**：设置页「模型服务 → 添加模型平台」中，远程派发的模型平台**不可删除**。

**实现**：
- 派发模型平台时打「受管标记」（`managed: true`）
- 注入器根据受管标记，隐藏该平台的**删除按钮**（受管模型）
- 员工可查看/使用，但不可删除；只有服务端能通过 dispatch_provider action=remove 收回

### 6C.2 远程派发 SKILLS 不可删除（R4/R5 强化）

**需求**：设置页「技能」中，远程派发的 SKILLS **不可删除**。

**实现**：
- 派发 SKILLS 时打「受管标记」
- 注入器根据受管标记，隐藏该 SKILLS 的**删除按钮**（受管 SKILLS）
- 员工可查看/使用，但不可删除；只有服务端能通过派发回收移除

### 6C.3 受管标记统一机制（R5 强化）

**核心**：所有远程派发项（Agent/模型平台/SKILLS/MCP）统一打 `managed: true` 标记，注入器据此统一处理「锁死/隐藏删除按钮/只读」。

```
受管项（managed: true）
├── 删除按钮隐藏
├── 编辑只读（锁死）
└── Key 隐藏（如适用）
```

## 八、Sidecar（sidecar/）→ 常驻受管客户端

```
sidecar/
├── sidecar.py           # 主进程（常驻，连接服务端）
├── lib/
│   ├── cherry_client.py # 官方 API 客户端（✅ 已有）
│   ├── ws_client.py     # WS 客户端
│   └── sync.py          # 派发/回收执行器
```

**Sidecar 常驻职责**：
1. 开机自启，连接服务端 WS
2. 收到派发指令 → 调 `cherry_client` 执行（创建/更新/回收 Agent）
3. 收到模型管控指令 → 执行（派发/收回 `企_` 模型）
4. 收到 SKILLS 同步指令 → 写本地数据目录
5. 拉取锁死规则 → 应用到 UI
6. 监控 CherryStudio 升级 → 自愈重打补丁
7. **检测 Git Bash 依赖 → 缺失则远程安装最新版**（6B.1）
8. **Agent 包解包 → 创建/更新受管智能体（全维度）**（6B.3/6B.4）
9. 定时上报状态 + 使用数据（按需采集）
10. 断线自动重连

## 十、核心流程

### 10.1 设备上线
```
1. Sidecar 开机自启
2. 连接服务端 WS
3. 发送 register（设备信息 + token + cherry_version + git_bash_installed）
4. 服务端登记设备 → 返回「该设备应有哪些 Agent/SKILLS/模型/锁死规则」清单
5. **依赖检测：若缺 Git Bash → 服务端下发安装指令 → Sidecar 静默安装**（6B.1）
6. Sidecar 比对本地 → 差异同步（缺的创建，多的回收）
7. 拉取锁死规则 → 应用
8. 进入常驻监听
```

### 10.2 派发新 Agent（Web后台操作）
```
1. 管理员在 Web后台「上传 Agent 包」或「选择已有 Agent 版本」
2. 管理员「派发 Agent 企_客服助手 给 设备组A」
3. 服务端向组内每台 Sidecar 发 dispatch_agent（含 package_url + 受管标记）
4. Sidecar 下载 Agent 包 → 解包 → 调 cherry_client.create_agent() 创建（全维度）
5. 回执 dispatch_result
6. 服务端更新设备状态
```

### 10.3 派发/收回模型（R1，Web后台操作）
```
1. 管理员在 Web后台「派发 企_DeepSeek 给 设备组A」
2. 服务端发 dispatch_provider action=add
3. Sidecar 经注入器接口注入 provider（员工端 UI 锁死不可见）
4. 回执
5. 收回：发 action=remove，Sidecar 移除企_ 前缀项
```

### 10.4 锁死规则迭代（R5，Web后台操作）
```
1. 管理员在 Web后台改「锁死规则」
2. 服务端发 sync_lock_rules
3. Sidecar 拉取新规则 → 应用到 UI
4. 员工端锁死界面更新（无需重装）
```

### 10.5 升级自愈（R7，自动）
```
1. 员工升级 CherryStudio
2. Sidecar 检测版本/哈希变化
3. 从后端补丁库拉取对应版本补丁
4. 自动重打 UI 锁死
5. 恢复受管状态
```

### 10.6 数据采集闭环（R6）
```
1. Sidecar 按需采集使用数据 → 上报
2. 服务端存储 → 分析
3. 分析结果 → 驱动新 Agent/SKILLS 开发
4. 派发回设备
```

## 十一、关键设计决策

### D1 企业模型命名隔离（R1）
- 企业派发模型统一加前缀 `企_`（如 `企_DeepSeek`）
- 员工自配模型自由命名，互不干扰
- 收回时从预设层移除 `企_` 前缀项

### D2 Key 保护双保险（R2）
- 强方案：公司模型走**模型网关**，员工端只看到网关 URL，Key 藏网关侧
- 兜底：UI 锁死隐藏 Key 显示

### D3 Agent 完整打包 + 生产链路（R3）
```
agent-package.zip
├── agent.json            # Agent 定义（基础设置/提示词/工具/技能/高级设置）
├── skills/               # SKILLS 目录（含版本）
├── mcp/                  # MCP 配置
└── data/                 # 预设数据文件
```
- **生产链路（6B.4）**：调好的智能体用打包 SKILLS 打包 → 上传服务端 → 版本管理 → 下发
- 服务端版本管理，Sidecar 按版本同步

### D4 SKILLS 版本仓库（R4）
- 复用 NAS 分发思路（SKILL经验蒸馏.md）系统化
- `skills-repo/{name}/{version}/`
- Sidecar 拉取指定版本 → 写员工端 `.claude/skills`
- Agent 包引用 SKILLS 时指定版本（如 `skill-a@v1.2`）

### D5 自进化双路径（R6）
- ① 预设 SKILLS（Agent 自带进化逻辑）
- ② 服务端数据闭环（采集→分析→开发新 Agent/SKILLS 回推）

### D6 设备鉴权
- 每台设备唯一 `device_id` + 简单 token（老板已定）
- 服务端 WS 连接需 token，防未授权设备连入

### D7 派发幂等性
- 每个指令带 `request_id`，Sidecar 执行后回执
- 服务端记录已派发状态，重复派发不重复创建
- 断线重连后，服务端重发未确认指令

### D8 设备分组
- 支持按组派发（如「设计组」「客服组」）
- 组内设备统一收指令

### D9 离线处理
- 设备离线时，指令进入队列
- 设备重连后，服务端补发积压指令

### D10 锁死规则远程化（R5）
- 机制固定（注入器一次到位），规则远程拉取（JSON 配置）
- 改后端即可迭代锁死界面，不重发补丁包

### D11 升级自愈（R7）
- Sidecar 监控版本/哈希变化 → 后端补丁库拉对应版本 → 自动重打
- 放任升级 + 自愈（老板选 A）

### D12 Git Bash 依赖自动安装（6B.1）
- CherryStudio 智能体依赖 Git Bash；设备注册上报 git_bash_installed
- 缺失则服务端下发安装指令 → Sidecar 静默安装最新版

### D13 受管 Agent 不可删除（6B.2）
- 派发 Agent 打 `managed: true` → 注入器隐藏删除按钮
- 只有服务端能回收（dispatch_agent action=delete）

### D14 Agent 全维度控制（6B.3）
- 基础设置/提示词/工具/技能/高级设置全部可由服务端控制
- 员工端受管锁定不可改

### D15 受管项删除保护统一机制（6C）
- 所有远程派发项（Agent/模型平台/SKILLS/MCP）统一打 `managed: true`
- 注入器据此隐藏删除按钮 + 编辑只读
- 只有服务端能回收

### D16 Agent 包上传与版本管理（6B.4）
- 调好的智能体用打包 SKILLS 打包 → 上传 Web后台 → agents_lib 版本管理 → 下发
- 更新 = 上传新版本 → 下发；回收 = 移除

## 十二、技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 服务端框架 | Python FastAPI + uvicorn | 轻量、异步 WS 支持好、与 Sidecar 同语言 |
| Web 后台 | FastAPI + Jinja2 + 简单前端 | 轻量可视化 |
| WS 库 | `websockets`（服务端）/ `websocket-client`（Sidecar） | 成熟稳定 |
| 数据存储 | SQLite（起步）→ PostgreSQL（规模化） | 起步简单，可扩展 |
| 补丁包 | NSIS 安装器 | 标准 exe，含卸载 |
| Sidecar 常驻 | Python + systemd（Linux）/ NSSM（Windows） | 开机自启、崩溃自愈 |
| 设备注册表 | 内存 + SQLite 持久化 | 在线状态实时，历史持久 |
