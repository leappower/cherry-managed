## 二、40号机受管 key（managed_key）为何远程不可取

- 受管 API key（`feature.api_gateway.managed_key`，F-3）不在本仓（list.json 只含普通 api_key 且脱敏；sidecar config 为 dev 占位）。
- `GET http://HOST_40:23333/v1/admin/managed-key` 从远程访问返回 **HTTP 403 `{"error":"Forbidden: managed-key route is loopback-only"}`** —— 该端点**仅允许 40 号机本机 127.0.0.1 回环访问**（安全设计，防远程窃取）。
- 40号机无 SSH（22 超时）、SMB 枚举被拒（ACCESS_DENIED / ACCOUNT_RESTRICTION），本开发主机无对 40 号机的远程执行通道。
- 因此 **200→create→list→update→delete→回执 deployed_rev 的完整实测必须在本机（或持受管key方）执行**，我无法在本主机伪造证据。

## 三、40号机本机补实测命令（交接给受管侧/老板）

在 **40号机本机**（受管 Cherry 运行中，自带 sidecar 服务）执行：

```powershell

#    受管版配置读 feature.api_gateway.managed_key

# 2) 直测 200 列表
curl.exe -H "Authorization: Bearer $key" http://127.0.0.1:23333/v1/admin/agents
# 3) create
curl.exe -X POST -H "Authorization: Bearer $key" -H "Content-Type: application/json" `
  -d '{"name":"配置推送测试","type":"claude-code","model":"deepseek/deepseek-v4-flash","instructions":"受管推送验证"}' `
  http://127.0.0.1:23333/v1/admin/agents
# 4) list → 记录返回的 agent id
# 5) update 同 id（PUT 全量）→ 验证 instructions 变化且 id 不重复
# 6) delete 同 id
```
