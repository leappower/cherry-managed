# CherryStudio 企业受管版 · 完整交付与使用说明

> 版本：2026-08-24 | 适用于员工端 Cherry-Studio-2.0.7-x64-setup.exe + 服务器端 cherry-managed
> 一句话：**员工装一个安装包 → 连上服务器 → 服务器把调试好的 Agent 下发 → 员工直接用。**

---

## 一、整套系统是什么

```
┌─────────────┐        ┌──────────────┐        ┌──────────────┐
│   服务器端    │  WS 连接 │    员工端      │        │   员工本人     │
│ (181 管理后台)│◄───────►│ CherryStudio  │══════► │  直接使用 Agent │
│ 做包/下发/审计 │ 心跳+指令 │  +内置 sidecar │ 落盘   │  无需手动操作   │
└─────────────┘        └──────────────┘        └──────────────┘
```

**只有两类东西，没有第三类：**

| 组件 | 是什么 | 装在哪 | 谁用 |
|------|--------|--------|------|
| **服务器端** | 管理后台（做 Agent 包、统一下发、看设备/用量/审计） | 公司一台常驻机（181） | 你/管理员 |
| **员工端** | `Cherry-Studio-2.0.7-x64-setup.exe` 一个安装包（**内置 sidecar**，装完自动注册服务） | 每个员工的 Windows 电脑 | 员工 |

> ⚠️ **没有**单独的 sidecar 安装包。sidecar 已经打进行安装包，员工装 setup.exe 就有了。之前单独出现的一切 sidecar 相关东西都是开发/调试过程，不是交付物。

## 二、服务器端先准备好（只做一次）

服务器端 = 180 号机上的管理后台，`http://192.168.3.181:2334/admin/`，账号 admin/admin123。

### 服务器要做的事
1. **登录管理后台**：`http://192.168.3.181:2334/admin/`
2. **做 Agent 包**（三种方式任选，见第四节）
3. **把包推给员工机**（见第五节）

## 三、新员工安装（最核心，照做）

### 3.1 发放安装包
把 `Cherry-Studio-2.0.7-x64-setup.exe`（109MB）发给新员工。可通过共享网盘 / U盘 / 邮件。

### 3.2 员工双击安装
1. 双击 `Cherry-Studio-2.0.7-x64-setup.exe`
2. 一路「下一步」，装到默认位置（`C:\Program Files\Cherry Studio\` 或 `D:\Cherry Studio\`）
3. 安装器会自动做三件事（无需员工干预）：
   - 安装 CherryStudio 客户端本体
   - **把内置的 sidecar 放到 `安装目录\resources\sidecar\sidecar.exe`**
   - **用 NSSM 把 sidecar 注册成 Windows 服务 `CherrySidecar`（开机自启 + 崩了自动重启）**

### 3.3 员工首次启动
1. 桌面打开「Cherry Studio」
2. **首次启动会弹出「服务端地址配置」** —— 填入服务器地址：`192.168.3.181`（或公司在用 IP）
3. 保存后，sidecar 服务自动连接服务器，开始心跳 + 等待下发
4. 完成。**员工端什么都不用再管。**

> 判断装好没：员工电脑上「服务」里应有 `CherrySidecar`（正在运行）；服务器后台「设备」tab 能看到这台新设备上线（online=1）。

### 3.4 员工日常使用
- 服务器推给员工的 Agent，会自动出现在 CherryStudio 里（落盘 `%APPDATA%\CherryManaged\`）
- **重启一下 CherryStudio** 就能看到新 Agent
- 员工完全不需要任何手动配置/安装步骤

## 四、服务器怎么做 Agent 包（三种进料口）

| 方式 | 操作 | 适用 |
|------|------|------|
| **A. 新建** | 「包配置」→ 右侧表单填名称/版本/type/model/提示词 → 创建 | 从零做一个包 |
| **B. 从员工机导入** | 「包配置」→「📥 从设备导入」→ 选设备→列 Agent→导入为包 | 员工机已有调好的 Agent，直接收编 |
| **C. 从 .json 文件导入** | 「包配置」→「📄 从 .json 导入」→ 上传 .json → 落库 | 任意机器做好的包，导出 .json 搬过来 |

> ✅ 每个包都能「⬇ 导出 .json」—— 一份 `.agent.json` = 一份完整 Agent 包，可拷给任何人/任何服务器。

## 五、服务器怎么下发 Agent 给员工

1. 进「**推送Agent**」tab
2. 选要推的**配置包**
3. 选**目标设备**（单个员工 / 整个分组）
4. 点「推送」
5. 员工端 sidecar 自动接收 → 落盘 → 员工重启 CherryStudio 即用

> 全程在服务器端操作，员工零参与。

## 附 1：要不要重打包安装包？（2026-08-24 实测定案）

**结论：当前无需重打包。** 原因：
- 「服务器下发 Agent」功能（sidecar `dispatch_agent`）= 2026-08-12 已写，**8/19 的 2.0.7 安装包已包含**，员工装机即可接收派发。
- 「从设备收编 Agent」（sidecar `agent_list`）= 2026-08-23 新加。**只有作为 Agent 来源的那台员工机**需要升级 sidecar；普通接收端不需要。
- 所以：50 台员工机里，只要你指定某台（如 40 机）作为「Agent 来源机」，给它单独升级 sidecar（手动替换或在 40 机用 pyinstaller 重打即可），其余员工机用 2.0.7 原包照常接收。
- 什么时候需要整体重打安装包：当你想让**所有**员工机都能被收编（都能当 source）时，才需要重打含新 sidecar 的安装包（走 cherry-studio-managed CI，需等 GitHub Actions 配额恢复）。

## 附 2：40 机收编 → 派发全链路实测（2026-08-24 已验证）

| 步骤 | 操作 | 结果 |
|------|------|------|
| ① 源机 Agent 就位 | 40 机 CherryStudio 中有 UI-Demo-Agent | ✅ |
| ② 服务器收编 | 选设备→列 Agent→导入 → 自动建配置包 rev3（带 source_device/source_agent_id 溯源） | ✅ imported:true |
| ③ 服务器派发 | 推送Agent tab 选包→选目标设备→推送 | ✅ online_sent:1 |
| ④ 接收回执 | 派发日志 status=success，dispatch_result 回执 | ✅ |

> 唯一前提：作为 Agent 来源的 40 机 sidecar 需支持 agent_list（2026-08-23 新版，已在 40 机部署）。

## 七、常见问题

**Q: 员工机没连上服务器？**
→ 检查 Windows 服务里 `CherrySidecar` 是否 Running；首次启动是否填了对的服务端地址；两台机是否同网段。

**Q: 推了 Agent 员工看不到？**
→ 员工**重启 CherryStudio**。侧车落盘是自动的，重启才加载。

**Q: 员工重装/换电脑？**
→ 重装 setup.exe 即可，服务器重新推送一次。

**Q: 「从设备导入」员工机列表空白？**
→ 该员工机的 sidecar 版本需支持 agent-list（8/23 后构建的安装包/或手动更新的 sidecar）。主线下发不受影响，只有「从设备导入」这个可选项需要新 sidecar。

## 附：技术细节（给开发/运维）

- **架构**：员工端内置 sidecar（Python 打包 exe）用 NSSM 注册服务 CherrySidecar；sidecar 自动连服务器 `ws://服务器IP:2334/ws`；服务器通过 WS 指令下发（dispatch_agent / dispatch_provider / dispatch_skills）+ 反向收集（agent_list 从设备导入）。
- **安装包构建**：cherry-studio-managed 仓库 fork-win-build CI，从 cherry-managed master 现场 PyInstaller 打 sidecar.exe → extraResources 注入 → NSIS 出品 setup.exe。
- **服务器 API**：`/api/admin/*`，鉴权 `X-Admin-Token`（非 Bearer）。
- **配置**：员工机用户配置 `%APPDATA%\CherryManaged\config.json`（服务端地址、device_id、托管 key）。
