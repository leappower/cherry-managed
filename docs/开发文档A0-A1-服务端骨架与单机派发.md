## 二、A0：服务端骨架

### 2.1 技术栈
- Python 3.14（本机已有）
- FastAPI + uvicorn（WS 支持）
- `websockets` 库
- SQLite（`sqlite3` 内置）

### 2.2 服务端配置 `server/config.json`
```json
{
  "host": "0.0.0.0",
  "port": 2334,
  "token": "simple-token-001",
  "db_path": "data/devices.db"
}
```

### 2.3 WS 服务端 `ws_server.py`
- 监听 `ws://0.0.0.0:2334`
- 连接鉴权：首条消息必须带 token，否则断开
- 设备注册：收到 `register` → 登记到 `device_registry`
- 心跳：收到 `ping` → 回 `pong`，超时标记离线
- 消息路由：按 `type` 分发到对应 handler

### 2.4 设备注册表 `device_registry.py`
- 内存 dict + SQLite 持久化
- 字段：`device_id, hostname, os, cherry_version, online, last_seen, agents[]`
- 方法：`register() / unregister() / set_online() / set_offline() / get_all()`

### 2.5 数据存储（SQLite）
表 `devices`：
```sql
CREATE TABLE devices (
  device_id TEXT PRIMARY KEY,
  hostname TEXT,
  os TEXT,
  cherry_version TEXT,
  online INTEGER DEFAULT 0,
  last_seen TEXT,
  agents TEXT  -- JSON 数组
);
```

## 三、A1：单机派发闭环

### 3.1 Sidecar 常驻进程 `sidecar.py`
- 启动时读 `sidecar.json` 配置
- 连接服务端 WS（`ws://127.0.0.1:2334`）
- 发送 `register`（设备信息 + token）
- 进入监听循环，处理服务端指令

### 3.2 Sidecar 配置 `sidecar/config/sidecar.json`
```json
{
  "server_url": "ws://127.0.0.1:2334",
  "token": "simple-token-001",
  "device_id": "HOST_CHEN-001",
  "cherry_host": "127.0.0.1",
  "cherry_port": 23333,
  "cherry_key": "***"  // 本机 CherryStudio key
}
```

### 3.3 WS 客户端 `ws_client.py`
- 连接 + 重连（断线指数退避）
- 发送消息（register/ping/status/dispatch_result）
- 接收消息（dispatch_agent 等）
- 回调分发

### 3.4 派发执行器 `sync.py`
- 收到 `dispatch_agent` → 调 `cherry_client` 执行
- `create`：先查同名，存在则更新，否则创建
- `update`：PATCH
- `delete`：DELETE
- 回执 `dispatch_result`

### 3.5 派发调度 `server/dispatch.py`
- 服务端 CLI/API：`派发 Agent X 给设备 Y`
- 向设备 WS 发 `dispatch_agent`
- 记录派发状态（pending/success/fail）

## 四、消息协议（A0-A1 范围）

### 4.1 注册（Sidecar → 服务端）
```json
{"type": "register", "token": "simple-token-001", "device_id": "HOST_CHEN-001", "hostname": "HOST_CHEN", "os": "windows", "cherry_version": "2.0.0"}
```

### 4.2 派发（服务端 → Sidecar）
```json
{"type": "dispatch_agent", "action": "create", "agent": {"name": "企_测试", "model": "deepseek:deepseek-v4-flash", "instructions": "...", "accessible_paths": ["D:\\...\\Agents\\deployed"], "configuration": {"permission_mode": "bypassPermissions", "max_turns": 100}}, "request_id": "req-001"}
```

### 4.3 回执（Sidecar → 服务端）
```json
{"type": "dispatch_result", "request_id": "req-001", "success": true, "agent_id": "agent_xxx", "error": null}
```

### 4.4 心跳（Sidecar → 服务端）
```json
{"type": "ping"}
{"type": "pong"}
```

## 五、验收标准（A0-A1）

| # | 验收项 | 通过标准 |
|---|--------|---------|
| 1 | 服务端启动 | `ws://127.0.0.1:2334` 可连，token 校验生效 |
| 2 | 设备注册 | Sidecar 连上后，服务端登记设备，`online=1` |
| 3 | 派发 Agent | 服务端发 `dispatch_agent`，Sidecar 在 CherryStudio 创建 Agent 成功 |
| 4 | 回执 | Sidecar 回 `dispatch_result success=true` |
| 5 | 回收 Agent | 服务端发 `action=delete`，Sidecar 删除 Agent 成功 |
| 6 | 心跳/离线 | Sidecar 断开后，服务端标记 `online=0` |

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| WS 库版本兼容 | 用 `websockets` 稳定版，先本机验证 |
| Sidecar 常驻崩溃 | systemd/NSSM 守护，崩溃自启 |
| 派发重复 | `request_id` 幂等，同名先查再建 |
| 断线丢指令 | 服务端记录 pending，重连补发（A2 完善） |

## 八、开发顺序

```
1. server/config.json + main.py（WS 服务骨架）
2. server/ws_server.py（连接/鉴权/路由）
3. server/device_registry.py（设备注册表）
4. sidecar/lib/ws_client.py（WS 客户端）
5. sidecar/lib/sync.py（派发执行器）
6. sidecar/sidecar.py（常驻主进程）
7. server/dispatch.py（派发调度）
8. 集成测试（本机 + 188）
```
