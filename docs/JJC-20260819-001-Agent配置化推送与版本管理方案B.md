## 一、目标

将 Agent 从「临时代码/即时派发」升级为**配置化推送 + 版本管理**（方案B）：
- **配置化**：Agent 以稳定 config（定义/属性）为推送单元，服务端集中维护，向目标设备精准下发
- **版本化**：Agent 配置带显式版本号，服务端存版本历史，支持追踪/回滚/设备端按版本对账

## 二、现状核实（已实读 cherry-managed）

| 能力 | 现状 | 缺口 |
|------|------|------|
| 派发 | `server/dispatch.py`：dispatch_agent/provider/skills（在线直发 + 离线入队补发 + request_id 幂等） | ✅ 链路已通 |
| 对账 | `sidecar/reconcile.py`：服务端期望 vs 本地（missing/modified/extra），受管项按期望修复 | ✅ 内容级 diff |
| 设备绑定 | `device_registry` + WS register（设备级 managed_key 鉴权，JJC-20260818-001 已落地） | ✅ 设备可信 |

| **版本管理** | reconcile 是**内容即时比对**，无显式版本号、无版本历史、无回滚 | ⛔ 缺版本号追踪/历史/回滚 |

## 三、方案B 设计（核心）

### 关键认知（方案A vs 方案B）
- **方案A（已作废）**：服务端集中 agents_lib 模板库 + skills_repo 完整包存储 → 重、中心化存整包
- **方案B（本任务）**：**配置化推送**——服务端存 Agent **配置定义**（轻量 config），下发的是配置（非整包代码）；**版本管理**守护配置演进

### M4-1：Agent 配置仓库（服务端）
1. 新增 `agents_repo`（服务端）：按 `agent_name` 存 Agent 配置定义（agent.json 语义：name/description/model/system_prompt/accessible_paths/mcp 等）
2. 每个 Agent 配置有**版本号**：`rev`（递增）或 `version`（语义化）
3. 配置 CRUD：管理员可创建/更新 Agent 配置，更新即产生新版本

### M4-2：配置化推送（服务端 → sidecar）
1. `dispatch_agent` 升级：下发 `{agent_name, config, rev}`（配置单元 + 版本号）
2. sidecar 侧：按接收的配置创建/更新本地 Agent（复用现有 dispatch_agent 处理）
3. 配置 vs 代码边界：只推 config（定义/属性），不含业务代码二进制

### M4-3：版本管理与对账升级
1. `devices`/`dispatch_log` 记录各设备**已部署的 agent rev**
2. reconcile 升级：**按版本号比对**（服务端期望 rev vs 设备已部署 rev），不一致 → 标记 modified 触发重推；无版本则退化为内容比对（向后兼容）
3. 回滚：管理员指定历史 rev → 下发改版 → 设备回滚

### M4-4：管理入口（Web 后台，若批次F/G已建）
1. Agent 配置列表 + 版本历史 + 「回滚到 rev」操作
2. 设备部署状态（哪台设备在哪个 rev）

## 四、关键决策（NEEDS CLARIFICATION）

| # | 决策点 | 建议 |
|---|--------|------|
| CL1 | **「配置化推送」边界**：只推 Agent config 定义？还是含 model/llm 配置？是否含 skills/mcp 引用？ | config 含 Agent 定义（属性/model/提示词/mcp 引用），skills 包仍走独立通道（不混入） |
| CL2 | **版本号策略**：递增 rev（int）还是语义化 version（x.y.z）？ | `rev`（整数递增，简单可靠）为主，可选：语义化作副 |
| CL3 | **配置存储位置**：服务端新建 `agents_repo`（DB 表 or 目录）还是复用现有？ | 新建 `agent_configs` DB 表 + `agent_versions` 表（版本历史），不做大目录改造 |
| CL4 | **对账按版本**：设备上报已部署 rev，服务端 diff？还是仍内容比对？ | 双轨：有 rev 用版本比对，无 rev 退内容比对（兼容存量） |
| CL5 | **回滚范围**：本期是否做 Web UI 回滚？还是先 CLI/API 回滚？ | CLI/API 先做（本期），Web UI 回滚若批次F/G已建则顺带 |
| CL6 | **版本历史保留**：保留全部版本还是 N 个？ | 保留全部（磁盘 / DB 体积小），可选：仅保留最近 N |
